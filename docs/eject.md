# Eject M#

`msharp-eject eject <repo>` (or **Eject M#…** in the app) turns an M# repository into a plain .NET solution. M#'s generated code becomes ordinary committed source, and everything M#-specific is removed.

The app keeps working the same way afterwards: the generated code is the code it already ran. It still uses Olive until you run [Replace Olive](de-olive.md).

## Before you start

- **The generated code has to be on disk.** M# writes it during a normal build, so build the solution once the M# way (`msharp-build`, or Visual Studio on Windows). Alternatively, run eject with `--generate` on Windows, which runs M#'s own generation step first. That's the only part of the whole tool that needs Windows.
- **Commit everything.** Eject refuses to run on a dirty git tree, so its changes are the only thing in `git diff`.
- **If you changed M# definitions since the last build, rebuild first.** Eject warns when definitions are newer than the generated code. A fresh clone resets file times and can trigger that warning falsely.

## What it changes

| Change | Why |
|---|---|
| `.gitignore`: removes the ignores for `Domain/[GEN-*]`, `Website/Controllers/Pages|Modules`, `Website/Views/Pages|Modules`, `Website/app_Start/TaskManager.cs` and `M#/` | The generated code becomes source and gets committed |
| `.sln` / `.slnx`: removes the `#Model` and `#UI` projects, plus their configuration lines | They're the M# DSL |
| `M#/` (and `@M#/`, `_M#_TEMP/`): deleted | The definitions are replaced by their output |
| `MSharp` package references: removed from every project | |
| `<UsingTask … WebCompiler.*>` and its targets: removed | `SassCompiler.exe` only runs on Windows |
| `compilerconfig.json`, `compilerconfig.json.defaults` and the `SassCompiler.exe` folder: deleted | |
| Web project: adds a `CompileSass` target | Runs [Dart Sass](https://sass-lang.com/dart-sass/) via `npx` for each `compilerconfig.json` entry. It has MSBuild `Inputs`/`Outputs`, so it's skipped when no `.scss` changed. Set `-p:SkipSass=true` to turn it off. |
| Web project: adds a `RestoreFrontEnd` target | Runs `yarn install` (when there's a `.yarnrc` or `yarn.lock`) or `npm install`, only when `node_modules` and `wwwroot/lib` are both missing. This is the step `msharp-build` used to do. |
| Web project: adds `Microsoft.TypeScript.MSBuild` when there's a `tsconfig.json` | TypeScript compiles in `dotnet build` on every OS, without Visual Studio |
| `Dockerfile*`: retired `microsoft/aspnetcore*`, `microsoft/dotnet` and `mcr.microsoft.com/dotnet/core/*` images, and Windows `nanoserver`/`windowsservercore` tags, become `mcr.microsoft.com/dotnet/aspnet|sdk|runtime:<version>` | The version comes from the project next to the Dockerfile, so behaviour doesn't change |
| `.config/dotnet-tools.json`: removes `msharp-build` | |
| Root `.bat`/`.cmd` files that call `msharp`: deleted | The build is now `dotnet build` |
| `Website/Views/Web.config`: deleted | Legacy MVC 5 Razor config that ASP.NET Core ignores. It references `MSharp.Framework`. |
| `DB/Tables/-Warning!.txt`: deleted | It says the folder is regenerated by M#, which is no longer true |

Pinned tool versions: Dart Sass 1.107.0, Yarn 1.22.22, `Microsoft.TypeScript.MSBuild` 5.9.3. They're constants in `EjectTransforms.cs`.

Every edit keeps the file's encoding (BOM or not), its line endings, and everything before the root element of XML files. Running eject twice is safe: the second run finds nothing to do.

## Verification

Unless you pass `--no-verify`, eject:

1. builds the solution and runs its tests (`dotnet test` with a TRX logger) **before** changing anything, with `MSHARP_BUILD=FULL` so M#'s own build step stays out of the way
2. applies the changes
3. builds and tests again
4. reports success only if the build passes and no test fails that passed before

If something breaks, nothing is undone automatically. Look at `git diff`, and use `git checkout -- .` to undo everything. The log has the full build and test output.

## After eject

- Commit. The diff is the generated code being added and the M# parts going away.
- Run the audit again. The Geeks packages left are the Olive ones, and Replace Olive is the next step.
- The `DB/` scripts stay. They move to EF Core migrations with the data layer ([plan](plan.md)).
